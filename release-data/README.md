# 次回公開のデータ差分

商品・口コミの追加は、出典を検証した追加差分SQLとしてここに保存する。
Previewでは既存本番データを読むだけ。ここに保存したSQLをPreviewで適用するコマンドはない。
新D1作成・本番D1複製・DB昇格方式は採用しない。データは別途公開承認後に既存本番D1へ適用する。
mainのコード公開とD1更新は同時トランザクションではなく、D1適用時にデータが公開される。
履歴の migrations/ や seed.sql を再実行しない。全DBコピーで本番を上書きしない。
SQLごとに変更理由・出典・想定追加件数・重複回避方法・検証結果を記録する。
試験専用データは本番用SQLに含めない。既存IDと source_type/source_url を保つ。
適用前後に件数だけでなく既存行の内容・関連整合性を比較する。
本番適用は公開承認後のみ。詳細は ../DEVELOPMENT.md。

## 口コミの検証可能性（2026-10-16 追加ルール）
サンプル調査（`audit/review-source-20261016/`）で、既存の公開レビュー要約のうち確認先ページで対応する投稿を確認できたのは約半数だった。
原因：`review_sources` テーブル（個別レビューの識別子用）は存在するが、既存データでは1件も登録されておらず、確認先の多くが「商品のレビュー一覧ページ」の共有URLだった。

今後の追加分は次を満たしてから公開承認に出す。
- 1行＝1つの識別できる投稿。確認先URLに加え、投稿日・投稿者表示名（ハッシュ化可）・一覧のページ番号・取得日を記録し、`review_sources` に追加する（追加のみ。既存行は更新しない）。
- 原文は保存しない。要約と、検証用に原文の短い指紋（ハッシュ）のみ。
- 要約は生成AIが作成した場合、その旨を作業記録（PR・Notion）に残す。
- 追加前に、無作為に10%以上を確認先ページで再確認し、結果をPRに書く。見つからないものは追加しない。
- 猫のレビューを犬の体験として登録しない（確認先で犬・猫のどちらかを必ず確認）。
