## 0. 結論（先に要点）

1. **現在の本番サイトには、インデックス登録を技術的に妨げる不具合は見つからなかった（事実）。** サイトマップ30URLはすべて200・自己参照canonical・noindexなし・robots.txtで許可。Googlebotのスマートフォン用UAと通常ブラウザで同じHTMLを返す。www・http・.html・`/index` はすべて301で正規URLに統一されている。
2. Search Consoleの「ページにリダイレクトがあります（34件）」「代替ページ（適切なcanonicalタグあり）（5件）」は、**設計どおりに転送・正規化されているURLが集計されたもの**で、Googleの説明でも対処不要の区分（事実＋Google公式説明）。この2区分（39件）は「未登録66件」の6割を占めるが、問題ではない。
3. 実際に問題なのは「クロール済み・インデックス未登録（20件）」と「検出・インデックス未登録（7件）」。技術的にはGoogleが取得・登録できる状態であり、**Googleが登録する価値をまだ認めていない、または優先度を低くしている状態**と考えるのが最も整合的（仮説B1・B2）。
4. その背景として最も有力なのは、**コンテンツの独自性・付加価値の弱さ**（他サイトの購入者レビューを生成AIで要約したものが中心で、運営者の実体験・独自検証がない。共通テンプレートの商品比較記事が16本。出典が確認できない要約が多い）と、**公開から約10週間の新しいサイトで、評価・被リンク・クロール頻度がまだ低いこと**の組み合わせ。ただしGoogleの内部評価は見えないため、**実証済みの原因ではない**。
5. 技術面で見つかった実在の問題は次の3つ。いずれも未登録の主因である証拠はなく、補助的な要因（C）にとどまる。
   - **旧GitHub Pagesに9月4日時点の古いサイトの複製14ページが今も公開されている**（`https://erbse09.github.io/inu-taikenki/`）。canonicalが転送元の `.html` URLを指している。→ 運営者がGitHubの設定でPagesを停止することを推奨（コード変更不要）。
   - サイト公開1週目（9/7〜9/8）に全ページの正規URLを `.html` から拡張子なしへ変更している。Googleが最初に覚えたURLがすべて転送URLになった。
   - 一部の内部リンクが転送の発生する `.html` URLを指していた。→ **develop向けDraft PRで修正**（後述）。
6. 「以前は約30ページ登録されていた」という記録は、**今回のデータでは確認できない**。仮にその30件が9/4サイトマップの `.html` URLだったなら、正規URL変更で「リダイレクト」へ移っただけの可能性もある（仮説B3）。Search Consoleのグラフ（ページのインデックス登録レポートの推移）を運営者が確認すれば判定できる。
7. **毎月の再登録リクエストは、登録を早める効果がない**とGoogleが明言している（後述の出典）。手動リクエストを続けるより、登録される価値のあるページに作り替えることと、状態の定点観測に切り替えるべき。

### 3-2. 旧GitHub Pagesの重複（詳細）

- 9/2に GitHub Pages で公開（`c5fcfa4` Configure custom domain for GitHub Pages）、9/8に `CNAME` を削除（`5fd3e13`）。カスタムドメインは外れたが、**Pages自体は有効なまま** `https://erbse09.github.io/inu-taikenki/` でmainブランチ直下のファイルを配信し続けている。
- 配信されているのは main 直下の `index.html`・`about.html`・`pet-dryer.html` など14ページと `sitemap.xml`・`robots.txt`・`ads.txt`。**内容は9/4頃の旧版で、現行サイトと一致しない**（mainのファイルと実測でバイト一致を確認）。
- 旧版のcanonicalは `https://inu-taikenki.com/about.html` のような `.html` URLで、そのURLは現行サイトでは301転送される。Googleから見ると「別ホストの古い複製が、転送URLを正規だと主張している」状態。
- **影響の大きさは未確認**（github.io は運営者のSearch Consoleプロパティ外のため、登録されているか確認できない）。Googleは通常、canonicalと転送をたどって統合するので、これだけで未登録が起きている証拠はない。ただし、古い複製を残す理由はなく、停止のリスクも小さい。
- **推奨対応**：運営者がGitHubのリポジトリ設定 → Pages で公開を停止（Unpublish／Sourceを None）。コード・本番には影響しない。停止後は github.io が404になる。

## 4. コンテンツ品質・独自性の監査

Googleの検索品質の観点と、著作権・利用規約の観点は**別の問題**として分けて書く。

### 4-1. Google公式の考え方（要点、原文は第8章）

- 役立つコンテンツ：「他の人の言っていることを主に要約しているだけで、価値をあまり付け加えていないか」を自己評価の問いとして挙げている。出典を示すことは独自の努力の代わりにならない。生成AIで大量の文章を、人の監督・編集なしに作ることは「努力がほとんどない」とされる。
- 商品レビューのベストプラクティス：自分で使った証拠（写真・音声など）、独自調査に基づく長所短所、定量的な測定、競合との違いの説明を求めている。
- スパムポリシー：「大量生成されたコンテンツの不正使用」は作り方（AIかどうか）を問わず、ユーザーにほとんど価値のない独自性のないページを大量に作ることを指す。「スクレイピング」には他サイトの内容を少し言い換えて再掲するもの、「内容の薄いアフィリエイト」には独自の内容や付加価値のない商品説明・レビューの転用が含まれる。一方、良いアフィリエイトページの例として「商品やカテゴリのナビゲーション」「商品比較」を挙げている。

### 4-4. 利用許諾の問題（検索品質とは別の問題）

- 既存の利用条件監査（CONTROL ROOM 10/28〜10/30）：許諾を確認できる本人投稿は0件。楽天のレビュー規約（他者レビューの転載・転用・編集の制限）やYahoo!ショッピングのアフィリエイトガイドライン（レビュー転用の制限）との関係が未解決。
- これは**著作権・利用規約・AdSenseのコンテンツポリシーの問題**であり、Googleの検索の順位・登録の判断とは仕組みが別。Google検索が規約違反を自動で判定して登録しない、という証拠はない。
- ただし、「他サイトのレビューを要約して載せる」という同じ構造が、検索品質（付加価値の不足）と権利（許諾の不足）の両方の論点になっている。**解決の方向（許諾のある一次情報へ移る）が共通**なので、改善計画では一緒に扱う。

### 4-5. 判定

- 「AI生成」「口コミ要約」「アフィリエイト」の存在だけで低品質と判定されたとは言えない。Googleも作り方ではなく価値で判断するとしている。

## 10. 最終判断（質問への回答）

### Q1. 未登録問題は、技術的な不具合が主因と考えられるか？

**いいえ。** 現在の本番30URLにはnoindex・robots・canonical・ステータス・配信差の不具合がなく、URL検査でもハーネス記事は「インデックス登録可能」と判定されている。「リダイレクト34件」「代替ページ5件」は正常な転送・正規化の集計で、未登録66件の6割はこれで説明できる。技術面の実在の問題（旧GitHub Pagesの重複、公開1週目の正規URL変更、`.html` の内部リンク、307）は、主因ではなく補助的な要因と判断する。

### Q2. 記事の独自性・品質が原因である可能性はどの程度あるか？

**有力（信頼度：中〜高）。ただし実証はできない。** 体験の96%が他サイトのレビューの生成AI要約で、運営者の実体験・実測がなく、商品比較記事16本が共通の構成を持ち、出典を確認できない要約が非ハーネスで約半分ある。これはGoogleが挙げる「主に他人の意見を要約しているだけか」という問いに当てはまる。一方、文章の重複は少なく、方法の開示は誠実で、条件別の整理という固有の切り口もある。新しいサイトでクロール需要が低いこと（B2）との組み合わせで起きていると考えるのが最も整合的。

### Q3. 登録済みページが減ったという現象を、データから確認できるか？

**今回のデータでは確認できない。** 過去の「約30件」が同じプロパティ・同じ条件の数字かが不明で、Search Consoleの推移データも取得できなかった。9/4のサイトマップと canonical は `.html` URLで、9/7〜8に拡張子なしへ変更しているため、「`.html` URLが登録→転送になって外れ、新URLの多くが未登録」という置き換えでも説明がつく（B3）。Search Consoleの「ページ」レポートのグラフで判定できる。

### Q4. 今のまま記事を追加し続けてよいか、それとも品質改善を優先すべきか？

**品質改善を優先すべき。** 同じ型（公開レビューの要約中心）の記事を増やしても、登録されないページが増えるだけになる可能性が高く、権利の論点も広がる。まず2〜3本で一次情報・独自の判断材料を加えた改稿を試し、登録・表示回数の変化を見てから広げる。developにある公式仕様ベースの購入ガイド3本は性質が異なる（レビュー要約ではない）が、一次情報がない点は同じなので、公開するなら独自の判断材料を確認してから。

### Q5. 月に何度も手動で再登録リクエストをしなくて済むようにするには？

- 手動リクエストは登録を早めないので、**定期的なリクエスト自体をやめる**。重要な改稿をした時だけ、そのURLに1回。
- 代わりに、**月1回の定点観測**（第7章の8URLと登録数・表示回数・クロール統計）に切り替える。
- 登録が増える根本は、Googleが「登録する価値がある」と判断すること。一次情報のある記事への改稿と、正規URLの安定（今後URLを変えない）、旧複製の停止、サイトマップの正確さを保つこと。

### Q6. AdSense審査や今後の検索流入への影響をどう評価するか？

- **AdSense**：審査の仕組みは検索の登録とは別だが、AdSenseのポリシーも「有用性の低いコンテンツ」「権利を持たないコンテンツ」を対象にしており、論点が重なる。登録済みが6ページ程度で、独自の内容が少ない現状では、**再申請しても同じ理由で不承認になるリスクが高い**（推測）。改稿の効果が確認できてから再申請するのが妥当。第三者レビューの利用許諾の問題は、AdSense・アフィリエイト規約の面で別に解決が必要。
- **検索流入**：登録が6ページ程度の間は、流入は限定的なままと見込む。技術の修正だけで大きく増える可能性は低い。改稿した記事が登録され、表示回数が出始めるかどうかが最初の判断材料になる。
